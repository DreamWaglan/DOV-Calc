# 永久 ID、URL 与重定向规则

## 1. 适用范围

本规则适用于《拂晓手册》Wiki 的页面 ID、数据记录 ID、资源 ID、URL 路径、别名、锚点和重定向。目标是保证内容可引用、可迁移、可检查，并避免标题变更导致链接失效。

发布后已经公开的 ID 和 URL 视为稳定契约。除明显错误、安全风险或版权要求外，不得删除或复用。

## 2. 永久 ID 规则

1. 每个公开页面必须拥有全站唯一的 `id`。
2. `id` 发布后必须保持稳定。页面标题、导航位置、章节名称或 URL 调整，不应改变 `id`。
3. `id` 只能使用小写英文字母、数字和连字符。不得使用空格、下划线、中文、日期前缀或文件扩展名。
4. `id` 应表达内容主题，不应表达临时状态。例如使用 `combat-pve-team-building`，不得使用 `new-page-20260729`。
5. 数据记录 ID 必须在所属数据集内唯一。跨数据集引用时，应使用“数据集标识 + 记录 ID”的组合形式。
6. 资源 ID 必须与资产台账、来源记录和派生资源关联。派生资源不得拥有与原始资源冲突的独立来源身份。
7. 删除公开内容时，原 `id` 必须保留在历史记录或重定向登记中，标明替代页面或归档原因。

## 3. URL 路径规则

1. URL 使用稳定的英文小写短路径，单词之间使用连字符。
2. URL 应按信息架构分组，例如 `/start/beginner-guide/`、`/combat/pve-team-building/`、`/mechanics/damage-system/`。
3. URL 不得包含游戏版本号、发布日期、编辑者姓名、临时阶段名或文件来源名。版本信息由页面元数据表达。
4. 页面迁移目录时，应保留旧 URL 到新 URL 的重定向或别名记录。
5. 公开 URL 不得硬编码部署基址，例如 `/DOV-Calc/`。站点基址必须由构建配置统一注入。
6. URL 末尾斜杠策略由站点构建配置统一处理。同一页面不得同时暴露多个规范 URL。
7. 每个公开页面必须具有唯一 canonical URL。预览环境和生产环境不得产生互相竞争的 canonical。

## 4. Slug 与文件名

1. Markdown 文件名应与 URL 末段保持一致。
2. 目录索引页使用 `index.md`，其页面 ID 应表达目录主题，例如 `combat-index`。
3. 中文标题不直接作为文件名或 URL。中文标题通过 `title` 字段和页面正文呈现。
4. 页面拆分时，新页面必须申请新 ID。原页面保留自身 ID，并通过相关页或重定向指向拆分后的页面。
5. 多个页面标题相同或相近时，ID 和 URL 必须体现章节上下文，避免冲突。

## 5. Alias 规则

1. Alias 用于搜索、旧称、简称、常见误写和站内跳转兼容。
2. Alias 不得作为事实来源。别名只帮助读者找到页面，不证明名称正确。
3. Alias 可以使用中文、英文、简称或常见输入形式，但必须关联唯一目标页面或数据记录。
4. 一个 alias 指向多个目标时，必须创建消歧页面或在搜索索引中标记多义词。不得让同一 alias 静默覆盖旧目标。
5. 页面重命名时，旧标题应登记为 alias。若旧标题存在事实错误，应登记为“历史别名”，并在正文中说明现用名称。
6. Alias 的新增、删除和目标调整必须接受重复检查和搜索质量回归。

## 6. Redirect 规则

1. 公开 URL 变更时必须保留 redirect。直接删除旧路径会破坏外部引用和搜索结果。
2. Redirect 必须指向最接近原意的页面。没有替代页面时，应指向归档说明页或章节索引页。
3. Redirect 不得形成链式跳转或循环跳转。旧路径应直接跳到最终目标。
4. 因版权或安全原因撤下内容时，redirect 页面不得泄露受限正文、图片或附件。
5. `archived` 页面可以保留公开访问，也可以按 SEO 策略设置 noindex 或 redirect。具体策略必须在页面元数据中表达。
6. 发布前必须检查 redirect 目标存在、canonical 正确、站点地图不包含不应索引的旧路径。

## 7. 锚点规则

1. 标题锚点必须稳定。正文小节被其他页面引用后，章节编辑不得随意改名。
2. 长机制页、数据页和指南页应为关键结论、公式、字段说明和来源区块提供明确小标题。
3. 自动生成锚点出现冲突时，章节编辑必须调整标题或显式设置锚点，避免构建器生成不可预测后缀。
4. 删除小节时，应检查站内链接、搜索入口和外部引用。必要时保留短说明并指向新位置。

## 8. 冲突与保留

| 场景 | 处理规则 |
| --- | --- |
| 新页面 ID 与既有 ID 冲突 | 新页面必须改名。既有 ID 优先保留。 |
| 新 URL 与既有 URL 冲突 | 新页面必须调整 URL 或合并内容。不得覆盖已发布路径。 |
| 标题变更但主题不变 | 保留原 ID；旧标题登记为 alias。 |
| 页面合并 | 保留主页面 ID；被合并页面 URL redirect 到主页面或具体小节。 |
| 页面拆分 | 原页面保留 ID；新页面创建新 ID；原页面增加相关页或目录。 |
| 内容撤下 | 保留 ID 和撤下原因；受限内容不得继续公开。 |
| 数据记录更名 | 保留记录 ID；名称变化写入字段或别名。 |

## 9. 发布门禁

以下任一情况必须阻断发布：

1. 页面 ID、数据记录 ID、slug、URL 或 alias 出现重复冲突。
2. 公开页面缺失 ID、title、description、contentType、status 或 canonical。
3. Redirect 目标不存在、形成循环或链式跳转。
4. 站内链接、锚点、图片或附件引用不存在。
5. 公开产物中出现硬编码部署基址。
6. `restricted` 或 `pending` 内容通过旧 URL、alias、redirect、搜索索引或站点地图暴露。
7. 页面迁移后没有保留旧 URL 兼容策略。

## 10. 维护规则

1. 章节编辑负责在新增、移动、重命名或合并页面时更新 ID、URL、alias 和 redirect 登记。
2. 发布维护者负责在构建前执行重复 ID、断链、redirect、canonical、站点地图和部署基址检查。
3. 测试负责人负责维护 URL/base 解析、搜索别名和多视口路径的回归用例。
4. 事实审核人只在 ID、URL 或 alias 影响事实名称、历史称谓或版本语义时参与复核。
5. 每次正式发布必须记录 URL 变更摘要，方便回滚和外部链接排查。
