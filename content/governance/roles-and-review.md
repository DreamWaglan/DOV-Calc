# 角色职责与审核规则

## 1. 适用范围

本规则定义《拂晓手册》Wiki 在采编、事实核验、许可判定、构建发布和维护中的责任分工。所有公开页面、数据集、图片、附件和工具说明必须能够追溯到责任角色。

具体人员未知时，应记录责任角色并标记为“待指派”。待指派状态可以用于阶段内跟踪，但不得作为正式发布签核。

## 2. 角色定义

| 角色 | 主要职责 | 不承担的职责 |
| --- | --- | --- |
| 作者 | 提供原创内容、源文件、攻略观点、图片或外部原帖；确认署名方式和可公开范围。 | 不默认承担页面结构化、事实审核或发布操作。 |
| 章节编辑 | 拆分页面、组织标题层级、补齐 Frontmatter、维护相关页、处理导入草稿和移动端可读性。 | 不得绕过事实审核发布数值、公式和版本结论。 |
| 事实审核人 | 核对官方版本、数值、公式、适用版本、来源冲突和过期状态。 | 不负责替代作者授权，也不直接变更构建门禁。 |
| 版权/来源责任人 | 维护来源分级、许可状态、授权证据、隔离清单和待授权跟进。 | 不以口头判断替代授权证据。 |
| 数据维护者 | 维护规范数据源、数据集版本、字段说明、导入报告、记录数和漂移报告。 | 不通过页面 HTML 反向修补数据。 |
| 工具维护者 | 维护伤害计算器、装备速查和相关黄金样例；保证工具行为可回归。 | 不将公式变更混入框架迁移或样式调整。 |
| 发布维护者 | 执行安装、校验、测试、构建、部署、回滚和发布证据归档。 | 不得绕过来源、许可、Schema、断链、漂移或测试阻断。 |
| 测试负责人 | 维护测试规格、夹具、自动化报告、手工审阅清单和豁免记录。 | 不替代事实审核人确认游戏内容正确性。 |

## 4. 页面审核流程

1. 作者或章节编辑提交资料登记，记录来源、作者、发布时间、适用版本和许可状态。
2. 章节编辑将资料整理为页面或数据草稿，补齐 ID、标题、描述、页面类型、标签、相关页和来源区块。
3. 版权/来源责任人检查第三方正文、图片和附件的许可状态。`pending` 或 `restricted` 内容必须进入隔离清单。
4. 事实审核人核对版本、数值、公式、机制结论和来源冲突。未完成核验的时效性页面不得标记为 `current`。
5. 测试负责人或自动门禁检查 Schema、链接、资源、版本漂移、许可过滤、搜索和移动端要求。
6. 发布维护者只发布全部阻断项为 0 的构建产物，并记录提交 SHA、构建产物和回滚点。

## 5. 签核要求

| 内容类型 | 最低签核要求 |
| --- | --- |
| 站务页面 | 章节编辑签核；涉及发布流程时发布维护者签核。 |
| 普通指南页 | 章节编辑签核；包含时效性结论时事实审核人签核。 |
| 机制页 | 章节编辑和事实审核人签核。公式或计算示例必须可复算。 |
| 数据页 | 数据维护者和事实审核人签核。记录数、唯一键、版本和字段说明必须可追溯。 |
| 外部作者攻略转载 | 章节编辑、版权/来源责任人和事实审核人签核。 |
| 图片和一图流 | 章节编辑和版权/来源责任人签核；核心结论正文化后由事实审核人签核。 |
| 工具页面 | 工具维护者、事实审核人和测试负责人签核。 |

## 6. 待指派机制

1. 具体人员未知时，记录格式应为“责任角色：待指派”。不得使用虚构姓名、昵称或占位账号。
2. 待指派项必须包含任务范围、触发原因、需要的能力、最晚指派时间和临时跟进角色。
3. 阶段 0 可以存在待指派项，但退出阶段前，每个源文件、页面域、数据集和发布流程必须至少有一个明确责任角色。
4. 正式发布前，所有 A 类签核责任不得处于待指派状态。
5. 长期无人接手的待指派项必须降级为 `draft`、进入隔离清单或从发布范围中移除。

## 7. 冲突处理

1. 作者署名、许可范围或转载条件出现冲突时，由版权/来源责任人作发布判定。争议未解决前，受影响内容不得公开。
2. 数值、公式、机制或版本信息出现冲突时，由事实审核人作事实判定。无法判定时，页面状态必须为 `stale` 或 `draft`。
3. 页面结构、术语和阅读路径出现冲突时，由章节编辑提出调整方案，并保留原来源关系。
4. 构建、测试或部署阻断出现冲突时，发布维护者必须停止发布，并要求对应责任角色修正源头问题。
5. 任何角色不得通过删除来源、降低页面状态、绕过测试或手工改构建产物来隐藏冲突。

## 8. 豁免规则

1. 豁免只能用于无法自动检查但人工可接受的非阻断问题。来源缺失、许可不明、受限资源公开、重复 ID、断链、构建失败和黄金样例回归不得豁免。
2. 每项豁免必须记录责任角色、原因、影响范围、到期日期和替代验证方式。
3. 到期未处理的豁免必须重新评估。无法继续证明安全或正确时，相关内容不得发布。
4. 发布维护者必须在发布记录中列出仍有效的豁免项。

## 9. Phase 7 页面签核落地

2026-07-30 起，页面签核使用 `content/governance/page-review-decisions.json` 作为逐页审核总账。总账同时记录最终状态、编辑/事实/授权/数据工具/URL 历史审核轨道、责任组、内容哈希和下一次复核日期。

- `DOV-Calc 编辑审核组` 承担站务、目录和导航页的 A 类编辑签核；
- `暂无` 承担攻略、机制与专题页的事实签核；
- `DOV-Calc 工具与数据审核组` 承担已通过专项门禁的数据和工具页签核；
- `DOV-Calc 装备数据审核组` 负责 20260511 装备旧基线与 20260712 视觉参考的版本分层；
- `DOV-Calc URL 治理组` 负责旧路径、别名、锚点、canonical、noindex、搜索和 sitemap 边界。

这些名称表示仓库内可审计的责任组，不是对未知自然人身份的虚构。正式发布范围内不得再出现“待指派”或“待审核”作为 A 类签核人。
