# 术语表

## 1. 使用原则

本术语表用于统一《拂晓手册》Wiki 的内容治理、页面元数据、来源登记、审核和发布沟通。所有治理文档、页面模板、导入报告和门禁报告应使用本术语表中的名称。

同一概念必须使用同一术语。一个术语不得在不同文档中表达不同含义。新增术语前，章节编辑应先检查本文件是否已有可复用定义。

## 2. 内容与页面术语

| 术语 | 定义 | 使用边界 |
| --- | --- | --- |
| 公开页面 | 会进入正式站点 HTML、搜索索引和站点地图的页面。 | `draft` 页面不是公开页面。受限内容不得通过公开页面间接暴露。 |
| 草稿页面 | 用于导入、编辑或审核的内部页面。 | 草稿页面不得进入公开构建。 |
| 站务页面 | 说明来源、贡献者、版权、编辑规范、版本日志和治理规则的页面。 | 站务页面可以不绑定游戏版本，但仍应有维护责任人。 |
| 指南页 | 面向读者任务的攻略页面，说明适用对象、前提、步骤、误区和来源。 | 指南页可以包含观点，但必须区分事实与建议。 |
| 机制页 | 说明公式、机制、假设、样例和实验来源的页面。 | 机制页必须有事实审核人。 |
| 数据页 | 由结构化数据生成或展示的页面。 | 数据页不得从渲染后的 HTML 反向抓取数据。 |
| 专题页 | 围绕特定主题、角色、剧情、历史或玩法建立的聚合页面。 | 专题页应提供子页索引和来源说明。 |
| 内容状态 | 页面或数据记录的发布状态。 | 仅允许 `draft`、`current`、`stale`、`archived`。 |
| 时效性内容 | 会随游戏版本、活动、数值或社区共识变化而变化的内容。 | 必须记录适用版本、核验日期、来源和审核人。 |

## 3. 来源与许可术语

| 术语 | 定义 | 使用边界 |
| --- | --- | --- |
| 来源 | 支撑正文、数据、图片或结论的原始文件、外部页面、视频、公告或作者资料。 | 来源必须可追溯。不能用“群里说法”等笼统描述替代。 |
| 来源级别 | 对来源可信度和使用场景的分级。 | 仅允许 A、B、C、D 四级。 |
| 官方来源 | 久游官网、TapTap 官方论坛、官方 Bilibili 账号、官方直播与公告。 | 官方事实和版本基线优先使用官方来源。 |
| 结构化社区资料 | GameKee、BWIKI 等公开 Wiki 或资料站。 | 可用于交叉核对和组织参考，不自动等同官方事实。 |
| 原创作者攻略 | TapTap、Bilibili 或其他可公开索引平台上的作者原创攻略。 | 可支撑攻略观点，必须记录作者和授权状态。 |
| 讨论线索 | 贴吧等讨论区中的问答、争议、反馈或问题线索。 | 不能作为数值、设定或公式的单一事实源。 |
| 许可状态 | 对正文、图片、附件和派生资源公开使用权限的判定。 | 仅允许 `owned`、`authorized`、`quoted`、`pending`、`restricted`。 |
| 授权证据 | 证明外部内容允许本站公开使用的记录。 | 必须包含授权人、授权范围、授权日期和证据位置。 |
| 公开阻断 | 因来源、许可、Schema、断链、漂移或构建错误导致内容不得发布。 | 阻断必须可定位到页面、资源或数据记录。 |

## 4. 版本与数据术语

| 术语 | 定义 | 使用边界 |
| --- | --- | --- |
| 适用版本 | 内容结论适用的游戏版本或版本基线。 | 不得用文件修改时间、导入时间或发布时间替代。 |
| 核验日期 | 事实审核人完成核对并确认可发布的日期。 | 自动导入日期不等同核验日期。 |
| 版本漂移 | 页面、数据或图片所依赖的来源版本与当前基线不一致。 | 漂移必须触发复核、标记或发布阻断。 |
| 规范数据源 | 结构化数据的维护来源，例如版本化 JSON、TS 数据模块或经校验的导入结果。 | 页面展示结果和工具过滤结果必须来自规范数据源。 |
| 数据集版本 | 一组结构化数据的版本标识。 | 必须与来源文件校验值、导入时间、记录数和审核人关联。 |
| 源文件校验值 | 对原始 DOCX、XLSX、图片或附件计算得到的哈希值。 | 用于确认导入基线和发现源文件变化。 |
| 复核队列 | 因版本、来源、许可、数据或争议变化而等待审核的项目清单。 | 复核队列必须记录责任角色和触发原因。 |
| 黄金样例 | 用于证明工具迁移前后行为一致的输入、输出和精度基线。 | 业务规则变更不得混入黄金样例回归。 |

## 5. 资源与导入术语

| 术语 | 定义 | 使用边界 |
| --- | --- | --- |
| 资产台账 | 记录源文件、图片、附件、校验值、来源、许可、负责人和状态的清单。 | 本文件只定义术语，台账具体格式由内容工程规则定义。 |
| 导入报告 | DOCX、XLSX 或图片导入后生成的结构化审计结果。 | 必须列出成功项、失败项、未识别元素和人工处理建议。 |
| 隔离清单 | 记录转换失败、许可未明或不可公开资源的清单。 | 隔离项不得进入公开构建。 |
| 一图流 | 用于传播的长图或信息图。 | 原图可以作为附件保留，核心结论应拆为可搜索正文。 |
| 响应式派生资源 | 为不同视口、格式或尺寸生成的图片资源。 | 派生资源继承原始资源的来源和许可状态。 |
| 替代文本 | 描述非装饰图片内容和用途的文本。 | 复杂图还应有正文说明，替代文本不能只写“图片”。 |

## 6. 角色术语

| 术语 | 定义 | 使用边界 |
| --- | --- | --- |
| 作者 | 提供原创内容、源文件、攻略观点或图片的责任主体。 | 作者可以是外部作者、项目原创者或整理者，但不得虚构姓名。 |
| 章节编辑 | 负责拆分页面、结构化正文、补齐元数据和维护章节质量的角色。 | 章节编辑不自动承担最终事实签核。 |
| 事实审核人 | 对数值、公式、版本、来源和结论准确性进行核验的角色。 | 高风险机制页和数据页必须设置事实审核人。 |
| 发布维护者 | 负责构建、测试、部署、回滚和发布证据的角色。 | 发布维护者不得绕过许可或事实门禁。 |
| 版权/来源责任人 | 负责授权跟进、许可判定和来源证据维护的角色。 | 未指派具体人员时，必须登记为待指派。 |
| 待指派 | 具体人员尚未确定，但责任角色已经明确的临时状态。 | 待指派项不得用于满足最终发布签核。 |

## 7. 标准枚举

| 枚举类型 | 允许值 |
| --- | --- |
| 内容状态 | `draft`、`current`、`stale`、`archived` |
| 许可状态 | `owned`、`authorized`、`quoted`、`pending`、`restricted` |
| 来源级别 | `A`、`B`、`C`、`D` |
| 页面类型 | `guide`、`mechanism`、`data`、`topic`、`about` |
| 读者类型 | `beginner`、`regular`、`advanced`、`editor`、`maintainer` |

## 8. 禁用或限制用语

| 表述 | 处理规则 |
| --- | --- |
| 群文件来源 | 必须替换为具体源文件标识、作者或责任角色。 |
| 网上资料 | 必须替换为具体来源级别、标题和链接。 |
| 已授权 | 必须补充授权范围、日期和证据位置。 |
| 最新版本 | 必须替换为具体游戏版本或核验日期。 |
| 以后处理 | 必须替换为复核队列项、责任角色和下一次跟进日期。 |
| 默认公开 | 禁止使用。第三方内容采用默认不公开、证据后放行。 |
