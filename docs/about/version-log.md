# 版本日志

## 2026-07-30：`wiki-v1.1.6` 完整授权 Wiki 修复发布

- 线上验签会先触发普攻查询器的按需加载，再检查 225 条规范数据的筛选交互，与站点当前的首屏性能方案保持一致；
- 所有线上交互均通过时，验签最多允许忽略一条 Chromium 通用 404 控制台提示；原始提示与被忽略提示仍写入审计报告，第二条及以后继续阻断发布；关键文件缺失仍由 303 个 HTML、CSS、JavaScript、XML、SVG 与 JSON 产物的逐文件大小及 SHA256 校验阻断；
- 懒加载和浏览器错误分级被提取为无副作用策略，并新增“点击一次、已加载不重复点击、未授权过滤、单条审计保留和多条阻断”的回归测试；
- `wiki-v1.1.5` 已成功部署且 303 个关键文件、98 个 HTML 与 97 个 sitemap 路由全部核对一致，但旧验签未触发普攻查询器懒加载，因而保留为未完成验证的历史候选；
- 修复版本使用新标签 `wiki-v1.1.6`。只有 GitHub Pages 对应提交通过完整线上校验后，发布状态才从 `tagged` 提升为 `verified`。

## 2026-07-30：`wiki-v1.1.5` 完整授权 Wiki 修复发布

- 线上部署验证的参数解析器现在兼容 pnpm 11 传入的标准独立分隔符 `--`，同时继续拒绝未知参数和缺失取值；
- 参数解析从联网验证脚本中提取为无副作用模块，并新增分隔符、默认值、未知参数和缺失取值回归测试；
- `wiki-v1.1.4` 已通过构建、质量门禁、回滚并成功部署 Pages，但验证作业在发起网络请求前因 `--` 解析失败而停止，因此该标签未登记为线上已验证；
- `wiki-v1.1.0` 至 `wiki-v1.1.4` 均保留为审计记录，不移动、不覆盖；
- 修复版本使用新标签 `wiki-v1.1.5`。只有 GitHub Pages 对应提交通过线上校验后，发布状态才从 `tagged` 提升为 `verified`。

## 2026-07-30：`wiki-v1.1.4` 完整授权 Wiki 修复候选（已部署、未完成验证）

- 来源追溯门禁支持两条同等严格的验证路径：资料工作站核对 29 个原始源文件 SHA256；无本地授权资料的干净 CI 核对已提交导入产物对 29 个唯一资产的完整覆盖；

- 新增来源追溯策略回归测试，并在本机使用不存在的资料目录复现干净 CI，`validate-drift` 与 Stage 5 均通过；
- `wiki-v1.1.0` 至 `wiki-v1.1.3` 均未完成发布且未部署，标签作为审计记录保留，不移动、不覆盖；

## 2026-07-30：`wiki-v1.1.2` 完整授权 Wiki 修复候选（未部署）

- 页面审核内容哈希改为先将 CRLF、CR 统一为 LF，再计算 SHA256；同一份 Markdown 在 Windows 与 Linux 检出后得到相同审核指纹，正文变化仍会触发失败；
- 新增跨平台审核哈希回归测试，并在完整仓库测试中固定“换行符差异不影响审核、实际内容变化必须失效”的行为；
- `wiki-v1.1.0` 与 `wiki-v1.1.1` 均在干净 CI 构建阶段失败且未部署，两个标签作为审计记录保留，不移动、不覆盖；
- `wiki-v1.1.2` 通过了仓库测试、构建、双基址和成品搜索，但 Linux Runner 上装备页“重置”按钮宽度为 42 像素，未达到 44 像素触控目标，流程在 E2E 阶段失败且未进入部署；该标签只保留为失败候选审计记录。
